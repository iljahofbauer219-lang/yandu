# 砚都跨境 UI 验收清单

适用于页面、组件和视觉修复。勾选项必须通过实际操作、源码检查或截图确认；不适用项需记录原因，不得默认略过。

## 1. 业务与信息结构

- [ ] 页面标题、当前对象/店铺和当前阶段清楚可见。
- [ ] 用户能在 5 秒内识别当前唯一主任务。
- [ ] 同一操作组最多一个主按钮。
- [ ] 禁用操作显示未满足的条件。
- [ ] 成功、警告、失败、等待和运行中均有文字或图标，不只依赖颜色。
- [ ] AI 或合规结论具备证据、规则或可展开详情。
- [ ] 空状态、加载失败和无权限状态可区分且可恢复。

## 2. 组件状态

- [ ] Button 覆盖 default、hover、active、focus-visible、disabled、loading。
- [ ] Field 有可见标签、焦点态、错误态、修复说明和关联描述。
- [ ] 可点击 Card 可通过键盘聚焦和触发；不可点击 Card 不伪装成交互控件。
- [ ] Modal 打开后焦点进入，关闭后返回触发控件，Escape 行为正确。
- [ ] Menu 不超出窗口，并支持键盘选择和关闭。
- [ ] Toast 不承载必须阅读或必须处理的错误。
- [ ] 固定 ActionBar 不遮挡最后一项内容。

## 3. 视觉系统

- [ ] 新增颜色来自语义 Token；不存在可由现有 Token 表达的同义字面量。
- [ ] 品牌色、成功色和平台品牌色没有混用。
- [ ] 业务文字不小于 12px，正文默认 14px。
- [ ] 间距遵守 4px 序列；例外有组件或业务依据。
- [ ] 控件、卡片、弹窗和胶囊圆角符合 8/12/16/999px 层级。
- [ ] 同一页面可感知表面层级不超过三层。
- [ ] 深色主题保持相同的信息层级和状态语义。

## 4. 无障碍

- [ ] 正常文字对比度 ≥ 4.5:1；大文字和关键非文本边界 ≥ 3:1。
- [ ] 仅使用键盘可以完成核心任务。
- [ ] Tab 顺序与视觉顺序一致，焦点始终可见。
- [ ] 图标按钮和非文本控件有准确的可访问名称。
- [ ] 异步任务的重要开始、结果和错误可被辅助技术感知。
- [ ] 表单错误与对应控件关联，提交失败后可定位到首个错误。
- [ ] 文本放大到 200% 后仍可读、可操作，无关键内容丢失。
- [ ] 减少动态效果设置下无非必要位移或循环动画。

## 5. 窗口与主题矩阵

每个核心流程至少检查以下组合：

| 窗口 | 浅色 | 深色 | 要点 |
|---|---|---|---|
| 1180×720 | 必测 | 必测 | 无遮挡、关键操作可达、固定栏不覆盖 |
| 1440×900 | 必测 | 必测 | 推荐密度、并排信息层级正确 |
| 1024×720 | 建议 | 建议 | 最小工作宽度降级合理 |
| 1920×1080 | 建议 | 建议 | 内容不过度拉伸，阅读行宽受控 |

- [ ] 无意外横向滚动。
- [ ] 长标题、中英文混排、最大数字和空数据均检查。
- [ ] 浏览器/Electron 缩放 100% 下通过，不用缩放掩盖布局问题。

## 6. 工程检查

- [ ] `pnpm typecheck` 通过。
- [ ] `pnpm build` 通过，且确认构建时间与本次修改一致。
- [ ] 相关自动化或业务测试通过。
- [ ] 源码中没有新增无理由的 `!important`、全局元素覆盖或重复 Token。
- [ ] 控制台无本次修改引入的错误和关键警告。
- [ ] 对比修改前后的目标宽度截图。
- [ ] 在实际 Electron 窗口走通核心路径，确认加载的是本次构建资源。

## 8. 第一阶段文档验收

第一阶段不改运行界面，适用以下验收：

- [ ] 设计系统覆盖品牌、状态、排版、间距、组件、业务模式、主题、桌面适配和无障碍。
- [ ] 审计数字可由源码扫描复现。
- [ ] 每个主要问题都有证据、风险和后续处理阶段。
- [ ] 后续 UI 修改有可执行、可记录的验收清单。
- [ ] 文档之间链接有效，且未修改业务源码。
