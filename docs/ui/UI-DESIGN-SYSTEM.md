# 砚都跨境 UI Design System v1.0

适用范围：Electron 桌面端渲染层，包括 eBay 工作台、商品与仓库、AI 优化、合规知识库、发布、在线顾问、登录和系统管理。

## 1. 设计目标

界面应帮助跨境运营人员快速回答四个问题：现在在哪一步、系统掌握了什么证据、当前有什么风险、下一步能做什么。

设计原则按优先级排列：

1. **业务状态清楚**：通过、警告、失败、等待和运行中必须可区分，不能只依赖颜色。
2. **主任务优先**：同一操作区原则上只有一个主按钮；辅助操作降低视觉权重。
3. **证据可追溯**：AI 结论、合规判断和发布结果均应显示来源、条件或可展开详情。
4. **一致而非单调**：组件语言统一，不同业务阶段允许使用受控的辅助色。
5. **桌面效率优先**：本产品是桌面工作台，优先支持信息密度、键盘操作和大屏并排任务，不照搬移动端布局。
6. **渐进迁移**：保留现有业务结构，禁止为统一视觉而一次性重写页面。

## 2. 设计 Token

以下名称是第二阶段实现 Token 时的目标接口。现有变量可逐步映射，不要求一次性重命名。

### 2.1 品牌与中性色

| Token | 建议值 | 用途 |
|---|---:|---|
| `--yd-brand` | `#0ABAB5` | 品牌标识、选中态、关键链接 |
| `--yd-brand-hover` | `#079D98` | 品牌控件悬停 |
| `--yd-brand-soft` | `#E1F8F6` | 选中背景、轻提示 |
| `--yd-brand-contrast` | `#075955` | 品牌浅底上的文字 |
| `--yd-canvas` | `#F5F6F7` | 应用背景 |
| `--yd-surface` | `#FFFFFF` | 主面板、卡片 |
| `--yd-surface-muted` | `#F7F9F9` | 次级区域、只读区域 |
| `--yd-text` | `#1D2421` | 标题、正文 |
| `--yd-text-secondary` | `#66716C` | 辅助文字 |
| `--yd-text-muted` | `#858E89` | 非关键元数据，使用前必须检查对比度 |
| `--yd-border` | `#DFE5E2` | 默认边框与分隔线 |
| `--yd-border-strong` | `#C8D1CD` | 强边界、输入框悬停 |

Tiffany 青是品牌色，不等同于“成功”。品牌选中态与业务通过状态必须分别使用对应 Token。

### 2.2 语义状态

| 状态 | 前景 | 浅背景 | 图标/文本要求 |
|---|---:|---:|---|
| 成功/通过 | `#147453` | `#E2F6EF` | `✓` + “已通过/已完成” |
| 警告/待复核 | `#8E6015` | `#FFF7E4` | `!` + 明确风险或待办 |
| 错误/阻断 | `#A33D36` | `#FFF0EE` | `×` + 原因和修复入口 |
| 信息/运行中 | `#2563EB` | `#EFF6FF` | 信息图标或进度 + 状态文本 |
| 未开始/禁用 | `#66716C` | `#F1F3F2` | 说明进入条件，不只降低透明度 |

状态色只能表达业务语义。阶段装饰色、平台品牌色和数据系列色不得复用错误/成功语义。

### 2.3 排版

首选字体：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Microsoft YaHei", sans-serif`。数字密集区域启用 `font-variant-numeric: tabular-nums`。

| 层级 | 字号/行高 | 字重 | 用途 |
|---|---|---:|---|
| Display | 28/36px | 700 | 极少数总览关键数字 |
| H1 | 22/30px | 700 | 页面标题 |
| H2 | 18/26px | 650 | 大区块标题 |
| H3 | 16/24px | 650 | 卡片或步骤标题 |
| Body | 14/22px | 400 | 默认正文 |
| Body strong | 14/22px | 600 | 重点正文、控件标签 |
| Small | 12/18px | 400 | 元数据、说明 |

约束：

- 业务信息不得小于 12px；正文默认 14px。
- 10–11px 仅允许用于不影响决策的紧凑辅助标识，并需通过对比度和缩放检查。
- 小于 10px 禁止用于用户需要阅读或操作的内容。
- 中英文混排不得通过压缩字距解决溢出，优先换行、截断并提供完整内容入口。

### 2.4 间距、圆角、阴影与层级

- 基础单位 4px。
- 间距序列：4、8、12、16、24、32、48、64px。
- 控件圆角 8px；卡片 12px；大弹窗 16px；胶囊标签使用 999px。
- 禁止为相邻同层卡片随意使用 5、6、7、9、10、11、13、14、15px 等不同圆角。
- 面板层级优先依靠背景和边框；阴影仅用于悬浮菜单、弹窗、固定操作栏。
- 同一页面最多三个可感知表面层级，避免“卡片套卡片套卡片”。

### 2.5 动效

- 控件反馈 120–180ms；面板展开 180–240ms。
- 动效只用于确认因果关系、保持空间连续性或提示状态变化。
- 支持 `prefers-reduced-motion: reduce`，关闭位移、缩放和非必要循环动画。
- 加载超过 1 秒显示进度或阶段说明；无法估算时显示正在执行的任务，不使用无说明的永久转圈。

## 3. 布局与信息层级

### 3.1 应用框架

- 一级侧栏只承载产品模块；数量徽标用于真实待办，不作装饰。
- 平台内二级导航保持单行、固定顺序，并明确当前平台和店铺上下文。
- 页面标题区包含：页面名称、当前对象/店铺、关键状态和最多两个全局操作。
- 主内容区使用 `minmax(0, 1fr)`，避免长文本或表格撑破布局。

### 3.2 任务型页面

按以下顺序组织复杂 AI/合规流程：

1. 当前任务与完成条件。
2. 关键状态或阻断原因。
3. 用户需要确认的证据。
4. 参数和高级设置。
5. 日志、原始返回等诊断详情。

“下一步”操作应靠近完成条件；禁用时显示缺失条件，例如“需先确认 4 类图片”，不能只呈现灰色按钮。

### 3.3 数据型页面

- 筛选条件与结果数量放在同一上下文。
- 金额、比例和数量右对齐，并使用等宽数字。
- 表格或卡片行只保留一个主行操作，其余放入更多菜单。
- 空状态区分：尚未创建、筛选无结果、加载失败、无权限。

## 4. 基础组件契约

### 4.1 Button

变体：`primary`、`secondary`、`tertiary`、`danger`、`icon`。

- 同一操作组最多一个 `primary`。
- 默认高度 36px，关键流程 40px；图标按钮点击区不得小于 36×36px。
- 必须覆盖 default、hover、active、focus-visible、disabled、loading。
- 图标按钮必须有 `aria-label`；加载中保留原宽度并避免重复提交。
- `disabled` 附近必须可得知原因；高风险动作必须说明影响范围并提供确认。

### 4.2 Field

- 标签始终可见，placeholder 不代替 label。
- 输入、选择、数字和文本域使用统一边框、焦点环与错误位置。
- 错误文案说明如何修复，并通过 `aria-describedby` 关联。
- 必填项在标签处说明；提交失败后聚焦首个错误。

### 4.3 Card / Panel

- Card 表达一个对象或一组紧密相关信息；Panel 表达页面区域。
- 可点击卡片必须整体有键盘焦点和明确名称。
- 不可点击卡片不得添加误导性的 hover 位移或强阴影。
- 选中态同时使用边框/图标/文字，不只使用背景色。

### 4.4 StatusBadge / Notice

- Badge 用于短状态，不承载长解释。
- Notice 包含标题、说明、可选操作；阻断类必须给出修复入口。
- 成功、警告、错误和运行中必须同时有文字或图标编码。

### 4.5 StepProgress / ActionBar

- 步骤状态限定为未开始、当前、完成、警告、阻断。
- 已完成步骤允许返回，但返回不会隐式清空结果。
- 长流程使用固定 ActionBar 时，不得遮挡最后一项内容。
- 主按钮文案使用具体结果，如“确认图片并进入视频生成”，避免只有“下一步”。

### 4.6 Modal / Menu / Toast

- Modal 打开后焦点进入，关闭后回到触发控件；支持 Escape，破坏性确认除外。
- Menu 使用键盘方向键、Enter 和 Escape；不得超出窗口可视区域。
- Toast 用于操作反馈，不承载必须阅读的错误；关键错误应留在页面上下文。

## 5. 业务模式

### 5.1 eBay AI 优化

- 页面只强调当前阶段和当前可执行主操作。
- 事实卡、分镜卡、生成结果和质量闸门分别使用固定组件，不随阶段重新发明样式。
- “模型选择”属于参数层，“商品一致性/合规结果”属于证据层，两者不能争夺同等视觉权重。
- 所有自动重试、回退和人工接管必须显示次数及最终状态。

### 5.2 合规审核

- 风险等级与审核状态分开呈现，例如“高风险 · 待人工复核”。
- 结论必须附规则、适用站点、证据与建议动作。
- 红色只表示阻断或明确错误；待确认使用警告色。

### 5.3 在线顾问

- 任务、项目、会话、模型和权限形成稳定层级。
- 工具执行、审批请求和最终回答采用不同消息类型。
- 权限提升必须说明将执行的动作和影响范围。

## 6. 深色主题

- 深色主题是相同语义 Token 的映射，不是独立品牌。
- 避免纯黑大面积与高饱和荧光色长期对视；正文对比充分但不过曝。
- 所有浅色状态背景必须提供深色映射。
- 图片、平台 Logo 和商品图不得受通用反色滤镜影响。
- 浅色与深色主题必须使用同一状态名称、图标和交互结构。

## 7. 桌面适配

目标验证宽度：1180px、1440px；建议额外覆盖 1024px 最小工作宽度和 1920px 大屏。

- 1440px：完整功能和推荐信息密度。
- 1180px：允许次要列收缩或折叠，不得遮挡关键操作。
- 1024px：侧栏可紧凑，复杂双栏允许转为主次切换；不要求模拟手机布局。
- 高度 720px：固定栏不能遮挡内容，关键操作可通过滚动到达。
- 不以浏览器缩放替代响应式设计。

## 8. 无障碍最低标准

- 正常文本对比度至少 4.5:1；大文本和非文本关键边界至少 3:1。
- 所有功能可用键盘完成，Tab 顺序与视觉顺序一致。
- 所有交互控件有可访问名称，状态更新使用合适的 `aria-live`。
- 焦点指示器始终可见，不能只改变极轻微的边框颜色。
- 文本放大至 200% 后仍可读、可操作，允许布局重排。
- 不只依赖颜色、位置或动画表达结果。
- 表单错误、异步失败和权限阻断应主动关联到对应控件或区域。

## 9. 开发交接与例外

每次新增组件需记录：用途、变体、全部状态、键盘行为、尺寸、主题映射和使用禁忌。新增 Token 前先确认现有 Token 无法表达该语义。

业务紧急变更可以暂时例外，但必须在代码或任务记录中注明原因、影响页面和清理条件。禁止用新的全局覆盖文件长期修补单页问题。

## 10. 完成定义

页面只有同时满足以下条件才算 UI 完成：

- 业务路径实际可完成，错误与空状态可恢复。
- 组件和 Token 使用符合本规范。
- 键盘、焦点、对比度和可访问名称检查通过。
- 1180px、1440px、浅色、深色主题实际截图检查通过。
- 源码检查、类型检查和相关功能测试通过。
- 实际 Electron 窗口确认功能可见、可操作，且加载的是本次构建资源。
