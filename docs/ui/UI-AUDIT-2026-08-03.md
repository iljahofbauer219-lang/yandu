# 砚都跨境 UI 基线审计

审计日期：2026-08-03  
范围：`src/renderer` 中的 CSS、TSX、主题文件，以及仓库内现有 Playwright/E2E 截图。  
性质：静态基线审计；第一阶段未修改运行界面。

## 2. 已有优势

1. 已存在品牌主色、表面、文字、边框等基础变量，不需要从零建立。
2. `ui-readability.css` 已集中处理一轮字号、焦点和窄屏可读性问题。
3. 深色主题通过 `[data-theme="dark"]` 限定，大部分不会污染浅色主题。
4. eBay 流程已形成明确业务阶段和质量闸门，适合抽象 StepProgress、StatusBadge 和 ActionBar。
5. 仓库保留 1180px、1440px 及流程状态截图，可作为后续视觉回归基线。
6. 部分复杂控件已使用 `aria-label`、`aria-expanded` 等属性，迁移可沿用现有实践。

## 3. 主要问题与证据

### P0：业务可读性基线不稳定

- 共检测到 1,026 处小于 12px 的字号声明。
- `styles.css`、`image-studio.css`、`online-advisor-experience.css` 和 `ui-readability.css` 是主要集中区域。
- 现有截图中，阶段说明、计数、卡片辅助文本在整屏视图下明显偏小。

风险：用户可能看见状态却无法快速读懂进入条件、风险原因和辅助数据。

第二阶段要求：先处理核心流程中需要阅读和决策的信息；装饰性微文案最后处理，避免机械放大导致布局崩溃。

### P0：键盘焦点与异步状态反馈覆盖不足

- 20 个 CSS 文件中仅检测到 9 处 `:focus-visible`。
- TSX 中只检测到 1 处 `aria-live`，而项目包含采集、AI 生成、合规检测、发布和顾问执行等大量异步流程。

风险：键盘用户难以判断当前位置；生成状态变化可能不能被辅助技术感知。

第二阶段要求：基础 Button、Field、Menu、Modal 统一焦点契约；第三阶段为 eBay AI 优化增加阶段级状态播报。

### P1：Token 与颜色语义离散

- `styles.css` 中存在两个 `:root` 基础段，随后 `ui-readability.css`、在线顾问样式又定义独立变量。
- 颜色字面量共出现 3,654 次，格式归一前有 1,749 种写法。
- 品牌青、成功绿、深色荧光绿有时承担相近“积极状态”，语义边界不稳定。

风险：同一业务状态在不同页面颜色不同；新增模块倾向复制最接近的颜色而非复用语义变量。

第二阶段要求：建立一层兼容 Token，将旧变量映射至 `--yd-*`；禁止大爆炸式替换。

### P1：全局覆盖链过长

渲染入口依次加载基础样式、图片工作室、合规多阶段、可读性和深色主题。多个文件都能覆盖通用 `button`、标题、面板和布局规则。

风险：后加载修复解决一个页面的同时可能改变其他模块；实际效果依赖加载顺序。

第二阶段要求：新基础组件使用明确命名空间或组件类；现有页面逐步迁移后再删除旧覆盖，不能先调整加载顺序。

### P1：圆角、阴影和卡片层级过多

- 圆角高频值包括 8、9、10、12、7、14、6、11、18、13px 等。
- 复杂流程中多层卡片叠加，边框、背景和阴影同时存在。

风险：视觉层级依赖装饰差异而非信息结构，用户注意力被平均分配。

第二阶段要求：控件 8px、卡片 12px、大弹窗 16px、胶囊 999px；迁移时按组件边界归并，禁止全局正则替换。

### P1：复杂流程主操作不够聚焦

AI 优化页面同时显示阶段导航、质量说明、生成、确认和下一阶段操作。部分按钮使用大面积品牌色，当前主任务与未来动作容易竞争。

风险：用户知道流程存在，但不一定快速判断“现在唯一需要做什么”。

第三阶段要求：以 eBay AI 优化为试点，建立“完成条件 → 证据 → 主操作 → 参数/详情”的固定结构。

### P2：桌面适配有基础但缺少正式支持矩阵

- 已有 48 个媒体查询，但各业务样式自行选择断点。
- 现有截图覆盖 1180px 和 1440px，却没有统一记录最小宽度和高度验收要求。

风险：局部页面在目标宽度正常，新模块仍可能引入遮挡、固定栏覆盖或横向溢出。

本阶段已在设计系统和验收清单中固定 1180px、1440px，并建议补测 1024×720。

### P2：在线顾问形成相对独立的设计子系统

在线顾问样式约 2,347 行，包含独立变量、组件规则和深色主题映射。隔离降低了对主应用的污染，但会造成同品牌产品内组件表现不同。

建议：保留其隔离边界，第二阶段只映射品牌、文字、状态、焦点等顶层 Token，不急于合并全部 CSS。

## 5. 第二阶段建议变更面

建议新增而非直接拆毁现有文件：

- `src/renderer/ui/tokens.css`
- `src/renderer/ui/components.css`
- `src/renderer/ui/Button.tsx`
- `src/renderer/ui/Field.tsx`
- `src/renderer/ui/StatusBadge.tsx`
- `src/renderer/ui/Notice.tsx`

首轮只迁移跨页面高频且风险低的控件。`App.tsx` 体量大、工作区当前有用户修改，迁移前需先锁定试点范围并建立截图基线。

## 6. 基线复现命令

在仓库根目录执行：

```sh
wc -l src/renderer/*.css
wc -l src/renderer/*.tsx
rg -o --no-filename '#[0-9a-fA-F]{3,8}|rgba?\([^)]*\)' src/renderer/*.css | wc -l
rg -o --no-filename 'font-size:[[:space:]]*([0-9]|10|11)px' src/renderer/*.css | wc -l
rg -o '@media' src/renderer/*.css | wc -l
rg -o '!important' src/renderer/*.css | wc -l
rg -o ':focus-visible' src/renderer/*.css | wc -l
rg -o 'aria-live' src/renderer/*.tsx | wc -l
```

颜色唯一值统计需先统一十六进制大小写；本报告保留空格和透明度格式差异，目的是衡量字面量离散程度。
